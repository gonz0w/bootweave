# Portable reservation-bound capture evidence

On 2026-10-20 the closed reservation-bound capture sibling passed two focused
Mac groups: 116 independently frozen cases, 122 bounded launches and 244 retained
streams. See [results](reserved-capture-evidence/results.json) and the complete
[focused log](reserved-capture-evidence/focused.log). Full clean-candidate and
canonical source/review bindings are recorded separately in the PR.

The fixture uses real private inputs on fixed0/3/4, real material reservation and
known owned preparation/release. Only the capture translation unit's descriptor,
clock and transfer observations and selected material observations are modeled.
The fixed production scratch template is redirected only in the test object into
each retained private case. Inert two-line Ed representations need no signer,
private key, verifier process or listener. Rebound canary open-file descriptions
prove that refused repeats and later material cleanup do not close newly bound
input numbers. Exact anonymous-ready bytes, access, CLOEXEC and offset are checked.

Literal oracles cover spent original reservation time and exact two-second expiry;
cancellation, unavailable/invalid/backward clocks before input, during read/EINTR
and after final closes; each input close's EBADF versus unknown outcome; original
first cause; descriptor aliases, metadata and input refusal; all object-pair overlap,
overflow, invalid reservation shape and reuse. Failure followed by a valid direct
prepare request must create/write no member, even after external clock/flag faults
are removed in the test. Unknown input closure remains uncertain after known
scratch cleanup. No successful capture result grants authentication or operations.

The original source298 hashes before and after match. Every actual launch has its
own retained streams and consuming wait. The outer supervisor kept its leader
unreaped through its final original-group stop attempt, observed only that zombie
when Darwin refused the signal, consumed its actual wait and observed no remaining
group. Final direct-process rows and cleanup errors were empty. No recovered
identity or post-wait signal was used. Independent acceptance also checks the
retained actual results and fresh process absence; expected-negative result fields
are distinct from an unsuccessful fixture invocation.

The reused portable boundary has private HOME/tmp and a replaced environment,
270 seconds work/300 total, CPU90/process, fd128, CORE0, file128MiB, sampled512MiB
owned output and log8MiB. The unchanged owned launcher supplies compiler20 seconds
and driver4 seconds with smaller per-child CPU/fd/file/stream bounds. ASAN/UBSAN
are enabled, unsupported Mac leak detection disabled. No hard isolation/memory
claim or native resource sufficiency follows.

Capture uses8,093/8,192 source bytes, material15,466/18,432 and whole runtime
87,218/98,304. The complete fixed-object disjointness helper is counted in capture
C; existing shared implementation headers remain fully charged to their users.
The first over-budget draft was preserved unexecuted. A fixed-pair predicate,
existing full metadata comparison and one header reference to the complete
[normative contract](../design/authenticated-io.md#reservation-bound-capture-continuity)
provided a maintainable fit without a cap increase or hidden implementation.
All other source/runtime ceilings remain unchanged.

The CLI stays unlinked and legacy capture keeps its old behavior. Full startup
still needs an origin no later than first REAL timer arm, fixed monotonic signal
cancellation lifetime, exact native loader/fd/scratch confinement and OpenBSD
serial/plain/resource/cleanup qualification. Existing failed sequential-run
evidence and its custody gap remain preserved; this run does not repair them.
